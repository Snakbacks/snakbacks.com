How to Fuzzy Match in Google Sheets (3 Ways)

Written with AI assistance; tested in a real Google Sheet.

Google Sheets has no built-in fuzzy match. VLOOKUP, MATCH and XLOOKUP only find text that is identical, so "Inytech" will never find "Initech", and "ACME Pty. Ltd" will never find "Acme Pty Ltd". This page shows three ways to fix that, starting with the ones that need no add-on.

The problem in one example

You have a clean master list of customers with IDs, and a messy list from another system. You want the ID next to every messy name.

Master list (columns D and E):

  • Initech, 101
  • Umbrella Corp, 102
  • Acme Pty Ltd, 103
  • Globex Corporation, 104

Messy names (column A, starting at A2):

  • ACME Pty. Ltd
  • Inytech
  • Corp Umbrella
  • Globex

A normal VLOOKUP returns #N/A for all four. Each one fails for a different reason: punctuation, a typo, word order and a shortened name. No single trick fixes all four, which is why there are three methods below.

Method 1: clean both sides, then look up (no add-on)

This handles case, extra spaces and punctuation. It does not handle typos or word order.

In F2 on the master list, build a clean key and fill it down:

=LOWER(TRIM(REGEXREPLACE(D2,"[^\w\s]","")))

Then in B2, clean the messy name the same way and look it up against the key column:

=IFERROR(INDEX($E$2:$E$100, MATCH(LOWER(TRIM(REGEXREPLACE(A2,"[^\w\s]",""))), $F$2:$F$100, 0)), "")

"ACME Pty. Ltd" becomes "acme pty ltd", which matches the key for Acme Pty Ltd, so you get 103. The other three rows return blank, because they are not just a formatting difference.

If your spreadsheet uses a comma as the decimal mark, Sheets may want semicolons between arguments instead of commas.

Method 2: wildcards and word overlap (no add-on)

Use this when one name is a shortened version of the other.

Wildcard match

=IFERROR(INDEX($E$2:$E$100, MATCH("*"&A2&"*", $D$2:$D$100, 0)), "")

The asterisks mean "anything before or after". "Globex" is found inside "Globex Corporation", so you get 104. This only works when your messy text is contained in the master name, in the same word order.

Word overlap, for different word order

Put the messy name in G1, for example "Corp Umbrella". Next to each master name, in H2, count how many of its words appear in the candidate, and fill down:

=SUMPRODUCT(--ISNUMBER(SEARCH(SPLIT(LOWER(REGEXREPLACE(TRIM($G$1),"[^\w\s]",""))," "),LOWER(D2))))

Then pick the highest score:

=IF(MAX(H2:H100)=0,"",INDEX(D2:D100,MATCH(MAX(H2:H100),H2:H100,0)))

"Corp Umbrella" scores 2 against Umbrella Corp, 1 against Globex Corporation and 0 against the rest, so it returns Umbrella Corp.

Limits: it matches word fragments (the word "corp" is found inside "Corporation", which is why that row scores 1), and a single typo inside a word scores zero. Check the best match by eye, and only trust it when the winner clearly beats the runner-up.

Method 3: typo-tolerant matching

To catch "Inytech" you need an edit-distance measure, which counts how many single-letter changes turn one string into another. Sheets does not have one, so you add it yourself.

Option A: a small Apps Script function (free)

Open Extensions > Apps Script, paste this, and save:

function CLOSEST_MATCH(value, list, minScore) {
  var target = norm_(value);
  var min = (minScore === undefined || minScore === "") ? 0.8 : minScore;
  var items = [].concat.apply([], list);
  var best = "", bestScore = 0;
  for (var i = 0; i < items.length; i++) {
    var cand = norm_(items[i]);
    if (!cand) continue;
    var score = 1 - lev_(target, cand) / Math.max(target.length, cand.length);
    if (score > bestScore) { bestScore = score; best = items[i]; }
  }
  return bestScore >= min ? best : "";
}
function norm_(s) {
  return String(s).toLowerCase().replace(/[^\w\s]/g, "").replace(/\s+/g, " ").trim();
}
function lev_(a, b) {
  var prev = [], i, j;
  for (j = 0; j <= b.length; j++) prev[j] = j;
  for (i = 1; i <= a.length; i++) {
    var cur = [i];
    for (j = 1; j <= b.length; j++) {
      var cost = a.charAt(i - 1) === b.charAt(j - 1) ? 0 : 1;
      cur[j] = Math.min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost);
    }
    prev = cur;
  }
  return prev[b.length];
}

Use it in a cell, one row at a time, and fill down:

=CLOSEST_MATCH(A2, $D$2:$D$100, 0.8)

"Inytech" returns Initech. "Corp Umbrella" still returns blank, because the letters are in a different order. Custom functions are slow on thousands of rows, since each cell scans the whole list.

Which method should you pick?

  • Only case, spaces or punctuation differ: Method 1. Quick and exact.
  • Names are shortened versions of each other: Method 2, wildcard.
  • Word order differs: Method 2 word overlap, or the add-on.
  • Typos: Method 3, either option.
  • Thousands of rows, repeated often: the add-on, since the formulas fill a whole column in one go.

Choosing a threshold

Fuzzy matching returns a score from 0 (nothing alike) to 1 (identical). You decide the cut-off:

  • 0.9: strict. Very few wrong matches, but you will miss some real ones.
  • 0.8: a sensible default.
  • 0.7: loose. Catches more, and also produces more wrong matches.

Start at 0.8, then sort the matches by score and read the lowest few by eye. If they look wrong, raise the threshold. If real matches are being left blank, lower it. A blank cell is better than a confident wrong answer.

FAQ

Does XLOOKUP help?

Google Sheets has XLOOKUP, but it is an exact-match function. It will not forgive typos unless you pair it with a cleaned key column as in Method 1.

Is my data safe?

Methods 1 and 2 are plain formulas. The Apps Script runs under your own account. The Fuzzy Match add-on works inside the spreadsheet you open it in.

How big a list can I use?

Plain formulas handle thousands of rows comfortably. The Apps Script version slows down because each row is compared with every master row.
